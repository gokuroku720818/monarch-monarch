## V179: 울타리 건설 가능 위치 선택 오류 수정

울타리는 지면보다 한 층 위에 건설하지만 V178의 명령 UI는 작업 높이 판정을 생략하고 경로가 짧은 위치부터 선택했습니다. 예컨대 건설 목표 z=3에서 왼쪽 z=6 둑은 작업 사거리 밖인데도 선택되며, 작업 가능한 오른쪽 z=5 둑은 무시될 수 있었습니다. V179의 명령 가용성 및 위치 선택은 실제 `workFence()`와 동일한 작업 대상 높이를 사용합니다. 모두 접근 불가능할 때는 명령을 거부하고 기존 명령을 유지합니다.

실패 우선 회귀 테스트로 V178에서 잘못된 위치 선택을 확인하고 V179에서 유효 위치 우선 선택, 접근 불가 거부, 기존 울타리 상·하단 클릭을 검증했습니다. Node 검증 외에 경량판·전체판 각 75개 맵을 100틱씩 Chromium에서 실행했으며 JavaScript 오류나 시뮬레이션 정지 없이 검사 범위를 통과했습니다. MAP 75개, WAV 159개, 원본 이미지·음성 Base64도 보존했습니다. 구체적 범위와 한계는 [V179 보고서](V179_ORIGINAL_COMPARISON_REPORT.md)를 참고하십시오.

## V178: 높은 지형의 다리 건설 오류 수정

맵 M_000의 수면 `(16,7,2)`에 높은 둑 `(15,7,5)`의 병력으로 다리 건설 명령을 내리면 V177 UI는 다리 상판 z=3 기준으로 명령을 수락했지만, 작업 호출부와 `workBridge()`는 수면 z=2를 검사하여 작업을 거부했습니다. V178에서는 물 위에 건설할 때만 두 작업 판정을 모두 상판 `z+1`로 일치시켰습니다. 비용, 기타 전투·경제 규칙은 변경하지 않았습니다. [V178 비교 보고서](V178_ORIGINAL_COMPARISON_REPORT.md)
